# resid-msgpack

[MessagePack](https://msgpack.org/) as a format for
[resid-serial](https://github.com/larrydewey/resid-serial), the serialization framework. Any type with
`Encode`/`Decode` instances — written by hand or generated by `resid-derive`
— goes to MessagePack and back with these.

```resid
import "src/msgpack.resid";

Int main() {
    Result(List(Int), SerialError) bytes = to_msgpack(Point {.x = 1, .y = 2}) else { return 1; };
    println(msgpack_to_hex(bytes));                 // de 0002 d9017801 d9017902
    Result(Point, SerialError) back = from_msgpack(bytes) else { return 1; };
    println(f"{back}");
    return 0;
}
```

## Entry points

| Call | What it does |
|---|---|
| `to_msgpack(T x) -> Result(List(Int), SerialError)` | the bytes |
| `from_msgpack(List(Int) bs) -> Result(T, SerialError)` | one value, then `read_end` rejects trailing bytes |
| `to_msgpack_hex(T x) -> Result(Str, SerialError)` | the bytes as hex, for logs and tests |
| `from_msgpack_hex(Str hex) -> Result(T, SerialError)` | from hex |
| `msgpack_to_hex(List(Int) bs) -> Str` | any byte string as hex |
| `msgpack_encoder()` / `msgpack_decoder(bs)` / `msgpack_bytes(e)` | the raw states |

Every container states its own length, and there is no indefinite form, so
the decoder's state is only a stack of what each open container has left.

## How the data model maps onto MessagePack

| Resid | MessagePack |
|---|---|
| `Bool` | `true` / `false` (0xc3 / 0xc2) |
| `Int` | positive fixint, negative fixint, or int8/16/32/64 |
| `UInt(64)` | positive fixint, then uint8/16/32/64 |
| `Int(128)`, `UInt(128)` | the plain forms while they fit in 64 bits, otherwise an ext — type 2 for a positive magnitude, 3 for a negative one — wrapping the magnitude's big-endian bytes |
| `Float`, `Float(32)` | float32 when it reads back exactly, else float64; `NaN` and infinity have their own encodings here, so they are written rather than refused |
| `Str`, `Str(N)` | str8/16/32 |
| `ByteBuf`, `Bytes(N)` | bin8/16/32 |
| `Unit`, `Option(T)` `None` | nil |
| `Option(T)` `Some(v)` | `v` |
| `List(T)`, `Set(T)`, `List(T, N)` | array16/32 (a set in sorted order) |
| `Map(K, V)` | map16/32, sorted by key |
| a record | a map, the field names as str keys |
| a unit variant | its name as a str |
| a variant with a payload | a one-entry map `{name: payload}` |
| `Result(T, E)` | the enum `Result { Ok(T), Err(E) }`, so above |
| `Dec(N)` | its decimal text |

`Int(128)` and `UInt(128)` use the extension slot, which the specification
reserves for application types: type 2 and 3 stand for a positive and a
negative big integer, mirroring CBOR's bignum tags. A struct and a map are
one thing on the wire, and so are `Some(v)` and `v`, exactly as in serde.

## Files

| File | Contents |
|---|---|
| `src/msgpack.resid` | `Encoder(MsgpackEnc)` and `Decoder(MsgpackDec)`, the entry points |
| `src/pack.resid` | type headers, the fixed-width integer forms, UTF-8, IEEE-754 bits, hex |

## Tests

```sh
tests/run.sh             # RESIDC=/path/to/residc to pick the compiler
tests/run.sh --update    # rewrite the golden .out files
```

Five programs: the encodings the specification tabulates (`vectors`), the
whole model round-tripping (`roundtrip`), what bad bytes report (`errors`),
the `Value` tree (`value`), and instances generated by `resid-derive`
(`derive`). `run.sh` builds `resid-derive` from the sibling checkout and
regenerates `tests/model_serial.resid` before compiling.

## Requirements

A Resid compiler with the changes made alongside resid-serial (spec v3.8).
The framework lives in the sibling `../resid-serial` checkout; `resid.toml`
declares it as a dependency for the manifest tool, and `src/*.resid` import
it by path so an ordinary `residc` build works with no manifest at all.
